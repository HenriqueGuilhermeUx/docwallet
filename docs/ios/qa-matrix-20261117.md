## Segurança de documentos — migração Bearer em homologação, distribuição BLOQUEADA

- **Origem identificada:** o código anterior de `src/lib/backendDocuments.ts` criava `/api/documents/:id/download?s=<token de sessão>` e reutilizava o link em previews e no helper de compartilhamento. Trata-se de risco de exposição em URLs; **não há evidência de vazamento ocorrido**.
- **Contrato real do backend inspecionado:** `HenriqueGuilhermeUx/docwallet-backend/app.py`, rota `GET /api/documents/<document_id>/download`, decorada com `@require_auth`, lê `Authorization: Bearer` via `current_user_from_request()` e filtra o documento por `user_id=request.user.id`. O compartilhamento público é um fluxo independente via `createAccessLink` e `/api/shared`.
- **Correção isolada no frontend (ainda NÃO implantada):** `backendDocuments.toDocument()` não cria mais URL com sessão (`fileData: ''`); o download privado agora usa `fetchPrivateDocumentBlob()` (Bearer header, `no-store`, `credentials: omit` e `redirect: error`). O `DocumentViewerModal` usa URL temporária de Blob, revogada ao fechar e fecha quando a sessão é limpa. `DocumentCard` carrega miniaturas privadas com Blob temporário, apenas para imagens. O helper do hook passou a criar links temporários separados via `createAccessLink`. Sem fallback para `?s=`.
- **Evidências automáticas em andamento:** `private-download.test.ts` cobre autenticação HTTP mock e metadados sem token; `private-preview.test.tsx` cobre URL temporária revogada e encerramento da sessão. Confirmar **CI de branch atualizado** após os commits antes de declarar PASS.
